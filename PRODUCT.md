# Product

## Register

product

## Users

This project serves four overlapping audiences: the owner doing investment research review, friends or teammates reading and comparing reports, public readers browsing selected research, and future maintainers growing the repository into a small report library. Users arrive with different levels of context, but they all need to find a report, understand the conclusion, compare key signals, and read the supporting analysis without friction.

## Product Purpose

Finance Reports turns Markdown equity research reports in this repository into a GitHub Pages workbench. It helps readers filter reports by market, company, year, score, and action; compare conclusions and valuation ranges; and read the full report body in a clear long-form layout. Success means a new report can be added to the repository and become easy to browse, compare, cite, and revisit.

## Brand Personality

Refined, restrained, credible.

The interface should feel like a quiet research institute workbench: precise enough for investment review, polished enough for public reading, and calm enough for long sessions.

## Anti-references

Do not make this look like a dark neon trading terminal. Do not make it a generic SaaS card wall. Do not make a marketing landing page. Do not fill the interface with decorative charts, oversized hero claims, glassmorphism, or purple-blue gradient spectacle. Data components must help users filter, compare, read, or decide.

## Design Principles

- Put report reading before visual decoration.
- Keep the surface public-reader friendly while preserving enough density for research review.
- Use typography, white space, fine rules, and restrained blue-violet accents to create order.
- Make every data element earn its place by supporting filtering, comparison, or judgment.
- Favor familiar workbench patterns over invented affordances.

## Accessibility & Inclusion

Target WCAG AA. The interface should support keyboard navigation, visible focus states, reduced-motion preferences, and non-color-only state communication. Body text must maintain strong contrast on white and gray surfaces. Tables, filters, report selection, and section navigation should remain usable on mobile and desktop.
